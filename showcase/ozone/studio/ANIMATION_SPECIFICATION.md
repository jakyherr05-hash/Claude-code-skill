## 1 · Motion tokens
**Timeline unit.** 1 unit = 1vh (1svh at the S rig) of scroll distance, so master duration = scroll budget (desktop 1210, 390: 1010). Scrub distance = budget exactly = `.track` height (CSS `--budget`, keyed to `html[data-rig]`); the sticky `.stage` lives in `.story` above the track, so no extra 100svh is added to the track (TD1; A-1's budget arithmetic still holds). Scroll-driven tweens use units, never seconds. Seconds exist only in the loader, idle loops and hand-off. **These tokens are the only source:** `tokens.ts` and `registry.ts` are rewritten from this section (no demo values such as `dimmer`, `scrub:0.8`, `dur.xs:0.18`; registry registers ScrollTrigger and CustomEase only, no SplitText, no Flip; TD11, finding 24).
| Token | Value | Use |
|---|---|---|
| `--dur-xs / s / m / l / xl` | 0.12 / 0.2 / 0.3 / 0.7 / 1.5 s | xs hover/focus ring; s reduced-motion fade (≤200 ms cap); m prompt un-ink; l headline ink at hand-off; xl score fade-in |
| `ink` (CustomEase) | `M0,0 C0.22,0 0.14,1 1,1` | Signature. Wet-ink: a slow bloom at the nib, a quick stroke, a long soft settle. For every ink-in (headline masks, stroke-dashoffset draws, panel borders, wordmark, loader strokes). Tune by filmstrip, keep the name. |
| `cam` | `power2.inOut` | Camera moves inside a transition (zero velocity at both ends, so holds feel still). |
| `lift` | `power3.in` | Outgoing planes leaving (accelerate away, never ease into a stop). |
| `settle` | `power2.out` | Beam stop, card lift, paper rise. |
| `none` | linear | Master default, walk cycle distance, hold drift, tally scratches. |
| Windows | line 1 ink = 70–88 % of the incoming transition, line 2 = 85–100 %; hold drift = 2.5 % scale + 1 % x, linear | DESIGN §6.4 / CD §6 |
| Idle | breath 4 s loop (chest/shoulders 1.5 %), blink every 4–7 s, lamp shimmer; **stop 5 s after a hold begins, resume on next scroll** (WCAG 2.2.2) | Hold life only |
**Scrub smoothing: `scrub: 0.5` on fine pointers, `scrub: true` on `(pointer:coarse)`.** Why: a mouse wheel arrives in discrete 100 px steps, which would step the camera like a flipbook; 0.5 s of catch-up turns steps into a glide and is short enough that picture and scroll bar never disagree (all state is a pure function of the lagging playhead, so it is always coherent). Touch scrolling already has native momentum, and lag against a finger reads as drag. Not larger: a camera still travelling after the user stops would blur the "hold lands on text" contract. Re-check by wheel-sampling (§9). SFX and `setCue` read the playhead, not the scroll position.

## 2 · Global systems
- **Scroll:** native only. No Lenis, no ScrollSmoother, no `scroll-behavior:smooth` on `html` (it would fight scrub). Anchor jumps (`#scene-n`, "Skip to the message") use an instant JS `scrollTo` to the hold start of the target beat (`#beat-sN`); a hash present at load is handled the same way; focus moves to the heading. `history.scrollRestoration='manual'`. **Reload and deep link:** after the hand-off the page resumes at the stored scene or hash, applied with the playhead jump flagged so every `sfx:` cue is suppressed and only the latest `cue:sN` is applied (same rule as the 60-unit jump, §5). Resume never plays before the hand-off completes (TD10, finding 23).
- **Structure:** one sticky stage, one `gsap.timeline({paused:true, defaults:{ease:'none'}})` per matchMedia branch, one `ScrollTrigger` (`trigger: '.story', start:'top top', end:()=>'+='+track.offsetHeight, scrub, animation: master, invalidateOnRefresh:true`, **no `pin`**: the CSS sticky `.stage` pins, so there are no pin-spacers and no nested pins). CSS is the single source of the scroll length: master duration = budget units, and the check per rig is `st.end − st.start === track.offsetHeight` (TD1, finding 1). Camera values are functions of the stage size, so refresh re-evaluates them.
- **Rig selection (TD2, finding 2):** one `src/motion/rig.ts` exports the media-query strings for rigs L/M/P/S and for static (reduced motion, `max-height:359px`, `?view=text`). The pre-paint head script writes `html[data-mode][data-rig]` from those strings, CSS `--budget` keys on `[data-rig]`, and `gsap.matchMedia` uses the same strings: there are no width-based motion branches. The master rebuilds only when the rig bucket changes, with one 150 ms debounce (no 120 px height rule).
- **Labels (units).** Rigs L and M use the desktop column, S uses the 390 column, P = desktop × 0.9 with each **label** rounded to the nearest 5 (A-2, TD2; creative-director may tune after the filmstrip). The end value is the rounded label, not a rounded span. Position inside a transition is written as % of its span: `at = label + pct × span`; spans differ per rig, so every % in §5 holds in all rigs.

- **One-shot pieces** (everything else is scrubbed): loader, idle loops, hand-off timeline, footstep-frame callbacks. Every "swap" inside the master is `tl.set()` at a position, which GSAP reverses when the playhead goes back, so reverse is symmetric by construction. **Headlines and captions animate `opacity` or `clip-path` only, never `autoAlpha`, `visibility:hidden`, `display:none` or removal, so all seven headlines and all captions stay in the accessibility tree at every playhead (TD6, finding 7).**
- **No flashing:** headlight glare (t23, t34) ramps over ≥ 40 units; no >25 % luminance change more than once per second.

## 3 · Opening
- First readable content: S1 h1 is prerendered HTML in the document (in the accessibility tree and in no-JS from first paint); its **ink reveal stays** (creative intent): under `html.js-loading` it is clipped until the hand-off. No claim is made that it is the LCP element: LCP is whatever Chromium reports (expected: loader text) against the TECH §8 budget, and a separate **story-ready** time (hand-off) is reported by performance (G-2, finding 5). Story-mode intro adds light (bulb), depth (ink formation), identity (wordmark) and the protagonist; first visit ≈ 2.9 s of loader (silent), then **one hand-off of 1.65 s** (G-11, §7 arithmetic), plus 0.3 s (prompt un-ink) only when the prompt showed; the prompt itself adds stage 7 (2.9–3.3 s) before that. Story-ready (`performance.mark('story-ready')`) is the hand-off **end**: floor ≈ 4.55 s when autoplay is allowed (2.9 + 1.65), ≈ 5.2 s plus human decision time when the prompt shows. Returning visitor ≤ 1 s (compressed variant, §7). See §7.

## 5 · The six transitions (timeline specs)
Notation: `%` of the span; positions are start / mid / end. All tracks are children of the named sub-timeline added at its label. `tl.set` = reversible swap. "Continuous" items are never re-created. Every transition also gets `cue:sN` (audio `setCue(N, dir)`) at its 50 % label.

**t12 "The walk"** (span 100 / 80)
- camera: x +1.2 world widths (`cam`), scale 1.0 → 1.15; teen held at 40 % x (camera x follows `walkDist` proxy). Parallax planes by `data-depth`: railings/shelter 1.6, mid 1.0, skyline 0.3.
- character: 0 % turn ¾→side (pose set at 7 %, `tl.set`); 15–80 % walk, `walkDist` 0 → 4 steps, linear; 80–100 % decelerate to stand (frame snaps to `stand-uneasy` at 100 %). Balloon 1 enters at the right edge 80–100 %.

**SFX and cue direction (finding 22).** Every cue is a `tl.call(cb, [id], pos)` named by the labels above, but GSAP fires calls in both directions, so `cb` is a thin wrapper in `master.ts`. `master.ts` keeps the previous playhead and derives `direction = sign(playhead − previous)` once per update; the wrapper passes it on: `audio.sfx(id, {direction})` and `audio.setCue(N, direction)`. The audio module plays SFX only for direction +1 (bed-only on reverse, CD §7). **Reverse cues:** when the `cue:sN` label (50 % of the transition into scene N) is crossed backwards, `master.ts` calls `setCue(N−1, −1)` itself; the tween does not know. If one update crosses > 60 units (fling, anchor jump, reload resume), skip every `sfx:`, apply only the latest `cue:sN`.

## 9 · Performance rules
- **Properties:** `transform`, `opacity`, `stroke-dashoffset`, `clip-path` (and SVG `<mask>` element transform in t45). Never `filter` animation, layout props, `d` morphs, or `fill` tweens in scrub (fill colour changes are `set` swaps between two stacked layers). Reads before writes; no `getBoundingClientRect` in `onUpdate`.
- **Layers / will-change:** `will-change:transform` on `[data-cam]` and ≤ 3 of the heaviest planes, **always on** (a scrubbed stage animates continuously; others none). Max ≈ 12 promoted layers: camera group + 3 depth planes per scene, only for scenes within ±1 of the playhead. Ink-edge filter static on ≤ 3 layers. Halftone as static patterns, never re-rasterised by animation.
- **Node budgets (TD9):** document SVG nodes ≤ 20,000; rendered nodes in any frame ≤ 5,000 (3,600 at 390); prerendered HTML ≤ 250 KB gz. The art is prerendered and not hydrated, so the master only drives existing nodes.
- **Mount (TD9, finding 11):** `mount` is a `tl.set` of `display` on the art of scenes outside ±1 of the playhead, **only on aria-hidden art**. It never touches headlines or captions (TD6). Exempt from `mount`: the `sN-panel` low-detail groups in `<defs>` (≤ 300 nodes each; a `<use>` of a `display:none` element renders nothing, so they must stay mounted) and `red-all` (it spans the S2–S4 roughs and the eraser needs it; it has its **own node budget, counted separately from the per-frame total**, ≤ 600 nodes (G-4, TECH §8); it is `display:none` only by the t45 set at 60 %). **`content-visibility` is not used** (it does not apply to SVG children).
- **LOD swaps (reversible `set`s):** close-up head at t23 60 %, chest drawing at t34, distant-window ↔ interior at t56 45 %, panel art via the `sN-panel` groups in t67.
- **Lite tier (finding 27):** if the rolling frame time during loader stages 2–5 averages > 24 ms, `html[data-art=lite]` is set before the master is built: drop halftone patterns on planes with `data-depth` < 0.5, freeze far planes, halve crumbs and bloom circles. Loader frames include font decode and audio rendering, so the switch is not deterministic: **`?art=lite|full` overrides it** (QA and the prototype use it), and the chosen tier and its source (`override` or `auto`, plus the measured average) are always logged to the console and exposed as `window.__art` only when `window.__OZONE_QA__` is set (G-15).
